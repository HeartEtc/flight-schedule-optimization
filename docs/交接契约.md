## 四、★交接③ SQL → Python 回填（**最容易出错的一环**）

**问题**：`is_peak_hour` 是特征，但它的值由 SQL 的统计结论决定 → **必须先把 SQL 跑一遍，再把结果填回特征表**。

| 项 | 内容 |
|---|---|
| **交接文件** | **`data/output/peak_hours.csv`** |
| **列** | `hour`（0–23）、`flight_count`、`avg_delay`（1 位）、`delay_rate`（3 位） |
| **样例** | ```hour,flight_count,avg_delay,delay_rate```<br>```7,412,21.3,0.298```<br>```8,485,26.7,0.351``` |
| **B 的动作** | 把 `peak_hours.csv` **join 回** `flight_features.csv`，刷新 `is_peak_hour` 列，重新导出 |
| **硬要求** | **`is_peak_hour` 的唯一来源是这张表**——Python **不允许**自己写一套高峰判定逻辑 |

**验收（A 检查）**：
- [ ] 打印 `peak_hours.csv` 前 5 行贴群里
- [ ] 打印特征表里 `is_peak_hour == 1` 的 `sched_dep_hour` 去重值 → **必须与 `peak_hours.csv` 的 hour 集合完全一致**
- [ ] 分布检查：`is_peak_hour` 为 1 的占比 ≈ 高峰小时的航班量占比（不是 50%）

**为什么这一环最要紧**：模型学的"高峰特征"和报告里说的"高峰时段"如果不是同一套，**答辩时一问就穿帮**。

## 八、全组通用的四条格式铁律

| # | 铁律 | 违反的后果 |
|---|---|---|
| 1 | **UTF-8 无 BOM** | R 读出来首列名变 `X.U.FEFF.hour`；MySQL 导入首列报错 |
| 2 | **列名全小写 + 下划线，无空格无中文** | SQL 要加反引号、R 要改名 |
| 3 | **缺值用空字段**，不写 `NULL`/`NA`/`-` | `AVG()` 算错、R 把它当字符串 |
| 4 | **小数位数统一**（数值 1 位、概率 4 位、比率 3 位） | 报告里同一指标出现 `0.3` 和 `0.317` 两种精度 |

**检查 BOM 的一行命令**（Windows PowerShell）：
```powershell
Get-Content .\flight_features.csv -TotalCount 1 -Encoding Byte | Select-Object -First 3
# EF BB BF 开头 = 有 BOM，要去掉
```
