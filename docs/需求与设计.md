## 1. 原始需求（老师给的）

> 本项目聚焦某一机场早高峰或晚高峰时段的航班时刻微调优化。基于公开的航班时刻与延误数据，完成**数据清洗、高峰时段识别与延误趋势预测**，据此提出**将少量航班提前或推后 10—15 分钟的调整规则**，并通过**对比调整前后的延误指标**验证优化效果。研究以具体机场为案例，围绕真实运行数据展开，形成可操作的时刻调整方案。

老师补充：**每周投入不固定；数据目前拿不到（项目正式还没开始）；具体要求可以删减一部分再做。**

## 2. 需求拆解与"删减"决定

| 原始需求 | 技术本质 | 删减决定 |
|---|---|---|
| 数据清洗 | 读文件、过滤缺失值、字段规范化 | ✅ 保留（正好用 IO） |
| 高峰时段识别 | **按小时分组计数** | ✅ 保留（正好用 `Map`） |
| **延误趋势预测** | 高级版是回归/机器学习 | ❌ **删减**：改为"**按小时/航线统计平均延误与延误率**"。需求里这个结论本来就是用来支撑调整规则的，统计量足够 |
| 提出 10—15 分钟调整规则 | 基于统计结论做决策 | ✅ 保留（纯逻辑，不涉及算法） |
| 对比调整前后指标 | **同一套统计跑两遍** | ✅ 保留（复用已有代码） |

**一句话：本项目不做机器学习，做"数据清洗 + 分组统计 + 规则调整 + 前后对比"的完整数据流水线。**

## 3. 最终交付物

**一个 Java 命令行程序**，输入一份航班 CSV，输出四张统计结果 + 两个 CSV 文件（供 Excel 画图）。

```
输入：flights.csv
      字段示例：日期, 航班号, 航线, 计划起飞, 实际起飞, 延误分钟

流程：
  ① 读入全部记录 → List<Flight>
  ② 清洗：丢弃关键字段缺失/非法的记录，打印丢弃条数与原因分布
  ③ 按小时分组统计：每小时航班数、平均延误、延误率（延误 > 15 分钟的占比）
     → 由此识别"高峰时段"（航班数最多的若干小时）
  ④ 按航线分组统计：平均延误最严重的 Top 5
  ⑤ 调整规则：对高峰时段的航班，按规则计算"建议提前/推后分钟数"
  ⑥ 对比：对"原始数据"与"调整后数据"各跑一遍 ③④，输出对比表

输出：
  - 控制台：四张统计表
  - 文件：hourly_stats.csv、route_stats.csv（Excel 可直接画图）
  - 报告：把图表截图 + 结论写进 Word/PDF
```

## 4. 类设计

| 类 | 职责 | 字段/方法要点 |
|---|---|---|
| `Flight` | 一条航班记录（**数据类**） | `date`、`flightNo`、`route`、`schedDep`（计划起飞）、`actualDep`、`delayMinutes`；`isValid()` 判断能否参与统计 |
| `FlightAnalyzer` | 核心逻辑：清洗与统计 | `loadFromCsv(path)`、`clean()`、`countByHour()`、`avgDelayByHour()`、`delayRateByHour()`、`topDelayedRoutes(n)` |
| `Adjuster` | 调整规则的生成与应用 | `generateRules(peakHours)` 返回"哪些航班调多少分钟"；`apply(rules)` 返回调整后的新数据集 |
| `Report` | 输出与导出 | `printTable(...)`、`exportCsv(...)` |
| `Main` | 入口：串起整条流水线 | 菜单或直接按顺序执行六个阶段 |

**设计约束（写进注释）**：

- **不用任何第三方库**——只用 JDK 标准库（`List` / `Map` / `Stream` / `java.time` / IO）。**不引入 Python、不引入前端**
- 数据量不大（几千～几万行），**全部读进内存**即可，不做流式处理
- 图表**用 Excel 画**（导出 CSV → 打开 → 插入图表），**不为出图学新工具**
