# 项目分工：每个人具体干什么（可执行版）

> 制定：2026-10-13
> 项目：数据驱动的机场调度优化
> 用途：开工前跟队友对齐用。**每人看自己那一段，以及"我需要谁给我什么文件"。**

---

## 0. 一句话看懂整体

```
老师给原始数据
      ↓
【A · Java】清洗  ──▶ flights_clean.csv      ← 后面所有人都靠这个文件
      ↓
【B · Python+MySQL】入库 + SQL 统计 ──▶ *_stats.csv
      ↓
【D · R】画图 + 统计检验 ──▶ 图表 PNG
      ↓
【C】核对数据 + 写报告 ──▶ 报告.docx + PPT
```

**关键：每一段只有一个负责人，下一段只消费上一段的文件，不重复加工。**

## 1. A（本人）· Java · 数据清洗

**职责**：把老师给的原始数据变成"干净、格式统一、可以入库"的 CSV。

| 时间 | 做什么 | 交付物 |
|---|---|---|
| 第 1 周 | 确认字段含义；**先自造 20 行样例数据**给全组开路 | `data/sample/flights_sample.csv` |
| 第 2 周 | 写 Java 程序：读原始文件 → 清洗 → 输出 | `FlightLoader` 类 + `flights_clean.csv` |
| 第 3 周 | 补充数据质量处理（异常值、时间格式、重复记录） | 清洗日志（丢了多少条、按什么规则） |
| 第 4 周 | 配合 B 复核入库数据；复核全链路 | — |

**周投入**：**约 4 小时**（本项目为课余投入，需与其他课程平衡）

**你需要谁**：
- 老师 → 原始数据 + 字段说明
- C → **字段含义表**（第 1 周就要，你才知道每个字段是什么）

**你的产出被谁消费**：B（入库）、C（核对）

**要能回答的问题**：
- 清洗丢了多少条？按什么规则丢的？
- 为什么用 Java 而不是 Python？（答：我在学 Java，这个环节正好用上 IO 和集合）

## 2. B · Python + MySQL · 入库与统计

**职责**：把清洗后的数据入库，用 SQL 算出所有统计量。

| 时间 | 做什么 | 交付物 |
|---|---|---|
| 第 1 周 | 装 MySQL；**用 A 的样例数据**建表、写导入脚本 | `schema.sql` + `import_to_mysql.py` |
| 第 1 周 | 写环境安装说明（让全组能复现） | `docs/环境说明.md` |
| 第 2 周 | SQL 统计：按小时、按航线（含 Top N） | `hourly_stats.csv`、`route_stats.csv` |
| 第 3 周 | 调整规则的筛选 SQL + **调整后**的同一套统计 | `hourly_stats_adjusted.csv` |
| 第 4 周 | 索引优化、数据量大的查询调优 | — |

**周投入**：**约 5 小时**

**你需要谁**：
- A → `flights_clean.csv`（**格式在 `docs/大一年度项目-四人分工.md` 第 3 节定死**）
- C → 核对你的统计数字是否与原始数据对得上

**你的产出被谁消费**：D（画图）、C（核对与报告）

**核心 SQL（这是你这段的技术核心）**：
```sql
SELECT HOUR(sched_dep) AS hour,
       COUNT(*) AS flight_count,
       ROUND(AVG(delay_minutes), 1) AS avg_delay
FROM flights
GROUP BY hour
ORDER BY hour;
```

**要能回答的问题**：
- 高峰时段怎么定义的？为什么这么定义？
- 为什么要入库？直接读 CSV 不行吗？（答：数据量大时数据库更快；而且 SQL 统计比手写代码短得多）

## 3. C · 零基础 · 数据核对 + 报告

**职责**：**确保数字是对的**，并把整个项目写成能交的报告。

**你的活不依赖编程，但是全组最容易出事的地方。**

| 时间 | 做什么 | 交付物 |
|---|---|---|
| 第 1 周 | 把老师给的字段说明整理成**字段含义表**（字段名/含义/单位/取值范围） | `docs/字段说明.md` |
| 第 2 周 | **抽样核对**：Excel 打开原始数据，随机抽 20 行，逐行检查 A 的清洗结果——该丢的丢了没有？不该丢的丢了没有？ | 核对记录（含发现的问题） |
| 第 3 周 | 核对 B 的统计数字：手工用 Excel 算一遍某个小时的平均延误，和 SQL 结果对比 | 核对结论 |
| 第 3 周 | 用 Excel 根据 CSV 做初步图表 | 初版图 |
| 第 4 周 | **主笔写报告**（背景、数据来源、字段说明、数据质量问题、结论） | `报告.docx` 初稿 |
| 第 5 周 | 整理 PPT、组织排练 | 答辩材料 |

**周投入**：**约 5 小时**

**你需要谁**：
- A → 原始数据 + `flights_clean.csv`
- B → `*_stats.csv`
- 全组 → 各自章节的内容

**你的产出被谁消费**：全组（报告）

**为什么这不是打杂**：
- **四个人算出来的数字如果没人核对，出错就是全员背锅**。抽样核对是数据项目里最常被跳过、也最致命的一步。
- 报告必须有人主笔，否则最后一周全员赶稿、质量崩掉。

**成长路径**：先从 Excel 做起；上手后让 B 教你用 `pandas` 读 CSV 做同样的核对——**这是零基础学编程最自然的入口**。

**要能回答的问题**：
- 数据里发现过哪些质量问题？
- 你们的调整建议依据是什么？

| 第 2 周 | 延误分布图（直方图 / 按航线箱线图） | 图 2 |

## 5. 谁依赖谁（这张表决定"谁会卡住"）

| 依赖 | 给什么 | 什么时候要 | 卡住的后果 |
|---|---|---|---|
| A → B | `flights_clean.csv` | 第 2 周初 | B 无法入库，只能干等 |
| **C → A** | **字段含义表** | **第 1 周** | **A 不知道字段含义，清洗规则无从定** |
| B → D | `*_stats.csv` | 第 2 周中 | D 无图可画 |
| B → C | `*_stats.csv` | 第 3 周 | C 无法核对、无法写结论 |
| 老师 → A | 原始数据 + 字段说明 | 第 1～2 周 | **全组停摆 → 所以 A 先自造样例数据** |

**结论：第 1 周最关键的是两件事——A 造样例数据（解除 B/D 的等待），C 出字段含义表（解除 A 的等待）。**

## 6. 每周同步会（15 分钟，固定时间）

**每人只讲三句**：

```
1. 这周我产出了什么文件（给文件名）
2. 下周我需要谁给我什么文件
3. 我卡在哪（没有就说没有）
```

**规则**：
- **没有文件产出的人，要说清这周干了什么**（不能连续两周没有交付物）
- **改 CSV 列名必须在这个会上提出来**，不能自己偷偷改

---

## 7. 全组要守的三条纪律

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | **统计量只在 B 的 SQL 里算一次** | 各算一遍 → 报告里出现四个不同数字 → 答辩崩 |
| 2 | **CSV 列名固定，UTF-8 无 BOM** | 带 BOM 会让 R 读出乱码列名；改列名会让下游脚本全报错 |
| 3 | **原始数据不进 Git**，聚合结果进 Git | 原始数据几十 MB；聚合结果要能复现 D 的图 |
