# 大一年度项目：四人分工方案（最终版）

> 制定：2026-10-11
> 项目：数据驱动的机场调度优化（见 `大一年度项目-需求与设计.md`）
> **本文档取代之前的两人版与三人版。**

---

## 0. 成员与技能

| 成员 | 技能 | 定位 |
|---|---|---|
| **A** | Java 有基础；无 Python / SQL / R | **建模与规则生成** |
| **B** | 会 Python + MySQL | **建库、SQL 统计** |
| **C** | 编程零基础 | **数据校验、文档、报告** |
| **D** | 会 R | **可视化、统计检验** |

---

## 1. 核心原则

**① 每个环节只加工一次，下游只消费上游的产物。**
**② 谁算出来的数字就是唯一口径，其他人不重算。**

```
原始数据 ──A(Java)──▶ flights_clean.csv ──B(Python)──▶ MySQL
                                                │
                                                └──B(SQL)──▶ *_stats.csv ──D(R)──▶ 图表
                                                                  │
                                                                  └──C──▶ 核对 + 报告
```

**为什么必须这样**：四个人如果各算一遍"平均延误"，报告里会出现四个数字。**答辩时这是致命的。**

---

## 2. 四人分工

### A（本人）｜Java：原始数据 → 清洗后数据

| 任务 | 交付物 |
|---|---|
| 接收老师给的原始数据，确认字段 | — |
| **Java 读入原始数据**（`BufferedReader` / IO） | 读取类 |
| **数据清洗**：丢弃缺失/非法记录，统一时间与字段格式 | `flights_clean.csv` |
| 记录"丢了多少条、按什么规则丢" | 清洗日志 |

**技术路线**：`List<Flight>` / `ArrayList` / `HashMap` 分组 / `LocalDate` 解析 / 异常处理 —— **全部是已学或本周要学的内容**。

---

### B｜Python + MySQL：清洗后数据 → 统计结果

| 任务 | 交付物 |
|---|---|
| 设计并创建 MySQL 表（`flights` 表 + 索引） | `schema.sql` |
| **Python 把 `flights_clean.csv` 导入 MySQL** | `import_to_mysql.py` |
| **SQL 分组统计**：按小时、按航线 | `hourly_stats.csv`、`route_stats.csv` |
| 调整规则对应的 SQL（筛高峰时段航班） | `hourly_stats_adjusted.csv` |
| 环境安装文档（让全组能复现） | `docs/环境说明.md` |

**为什么给 B**：`GROUP BY hour, AVG(delay_minutes), COUNT(*)` **正是本项目统计量最自然的实现**——比 Java 手写循环更短更清晰。而且"CSV 导入数据库"是数据岗的日常操作。

---

### C｜数据校验 + 报告（零基础，但是硬需求）

| 任务 | 说明 |
|---|---|
| **字段含义表** | 整理原始数据每个字段的含义与单位（老师给的说明 → 表格） |
| **抽样核对** | Excel 打开原始数据，随机抽 20 行，**手工核对 A 的清洗结果**：该丢的丢了没有？不该丢的丢了没有？ |
| **异常值记录** | 记录明显不合理的数据（延误 9999 分钟、日期越界等） |
| **报告撰写** | 项目背景、数据来源与字段说明、数据质量问题汇总 |
| **答辩材料** | PPT 整理、排练计时 |

**为什么不是打杂**：

- **数据核对是数据项目里最常被跳过、也最容易出事的一步**。四个人做的统计没人核对，错了全体背锅
- **字段含义表是报告的必需章节**，也是全员理解数据的前提
- **报告必须有人主笔**，否则最后一周全员赶稿

**成长路径**：先从 Excel 开始；上手后让 B 带他学 `pandas` 读 CSV 做同样的核对——零基础最自然的编程入口。

---

### D｜R：统计结果 → 图表与检验

| 任务 | 交付物 |
|---|---|
| 读入 `hourly_stats.csv` / `route_stats.csv` | R 脚本 |
| 高峰时段图：小时航班量柱状图 + 平均延误折线 | 图 1 |
| 延误分布图（直方图 / 按航线箱线图） | 图 2 |
| Top N 延误航线横向条形图 | 图 3 |
| **调整前后对比图** | 图 4 |
| 统计检验（如调整前后延误差异是否显著） | 结论 + 检验结果 |
| 图表美化、统一配色、导出高分辨率 PNG | 报告用图 |

**边界**：**R 不做数据清洗，也不从原始数据重算统计量**——只消费 B 产出的聚合 CSV。

## 3. 文件流程与命名约定（避免"文件满天飞"）

| 阶段 | 文件 | 产出者 | 消费者 |
|---|---|---|---|
| 0 | `data/raw/flights_raw.csv` | 老师 | A |
| 1 | `data/output/flights_clean.csv` | **A** | B |
| 2 | `data/output/hourly_stats.csv` | **B** | D、C |
| 2 | `data/output/route_stats.csv` | **B** | D、C |
| 2 | `data/output/hourly_stats_adjusted.csv` | **B** | D |
| 3 | `report/figures/*.png` | **D** | 全体 |
| 4 | `report/报告.docx` | **C 主笔**，全员补充 | — |

**约定**：
- 所有 CSV：**UTF-8 无 BOM**（带 BOM 会让 R 读出乱码列名）
- 列名固定，**改列名必须提前在群里说**
- **原始数据不进 Git**（可能几十 MB）；`data/sample/` 放 100 行样例
- 聚合结果 CSV **要进 Git**，这样任何人都能复现 D 的图

---

## 4. 共同约定：接口格式

详见 `大一年度项目-两人分工.md` 第 4 节（CSV 列名与格式约定）。**核心三张表**：

```
flights_clean.csv  ：date, flight_no, route, sched_dep_hour, delay_minutes, is_delayed
hourly_stats.csv   ：hour, flight_count, avg_delay, delay_rate
route_stats.csv    ：route, flight_count, avg_delay, delay_rate
```

**先把格式定死，四个人就能并行开工**：A 造一份 20 行假数据 → B 就能写导入脚本 → D 就能写 R 脚本，**谁都不用等谁**。

## 5. 答辩分工（每人必须能讲自己那一段）

| 人 | 讲什么 | 可能被问 |
|---|---|---|
| **A** | 数据处理流程、清洗规则、Java 实现 | "清洗丢了多少条？判定标准？" |
| **B** | 数据库设计、SQL 统计逻辑、调整规则 | "高峰时段怎么定义？为什么这么写 SQL？" |
| **C** | 数据来源与字段含义、数据质量发现、结论建议 | "你们的建议依据是什么？" |
| **D** | 图表解读、统计检验、优化效果 | "调整后改善显著吗？怎么判断的？" |

**全员要能回答**："你们四个人怎么协作的？"
标准答案：**"我们用 CSV 作为各环节的接口，每一段只加工一次，避免多人算出不同数字。"** —— 加分答法。

## 6. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| **统计量被算多遍** | 报告里数字对不上 | 统计只在 B 的 SQL 做一次；A 只做清洗，D 只画图 |
| **C 被边缘化** | 老师看出来，C 答辩答不上 | C 的核对与报告是**硬需求**，每周要有产出 |
| **B 的环境搭不起来** | 全组卡住 | 第一周就产出环境文档，全组验证能跑 |
| **数据迟迟拿不到** | 项目停摆 | A 先造 20 行样例，把整条链路跑通；真数据到了只换文件名 |
| **字段含义不清** | 统计口径错 | **C 的字段含义表是前置任务**，第一周完成 |
| **四个人互相等** | 进度为零 | **先定 CSV 格式**，然后各写各的 |

## 7. 时间线（建议）

| 周 | A | B | C | D |
|---|---|---|---|---|
| 1 | 造 20 行样例；写清洗程序 | 搭 MySQL + 导入脚本 | 字段含义表 | 读 R 绘图基础 |
| 2 | 接真数据 → `flights_clean.csv` | SQL 统计 → 两份 CSV | 抽样核对清洗结果 | 用样例数据画出 3 张图 |
| 3 | 处理数据质量问题 | 调整规则 + 调整后统计 | Excel 初步出图 | 换真数据出图 + 统计检验 |
| 4 | 复核全链路 | 优化 SQL 与索引 | 写报告初稿 | 图表美化定稿 |
| 5 | 全员演练答辩 | 全员演练 | PPT + 排练 | 图表讲解演练 |

**每周一次 15 分钟同步**：每人说"这周产出了什么文件、下周需要谁给什么文件"。

## 8. 对 A（本人）的提醒

**你是唯一有 Java 基础的人**，大概率被默认成"技术负责人"。两件事必须注意：

1. **别把 B、C、D 的活也揽过来** —— 你写得比他们快，但那样他们答辩讲不出东西，老师会看出来
2. **项目投入封顶 4 小时/周** —— 你的主线（Java SE → 集合 → IO → 大数据栈）比这个项目重要得多。**项目里只做"能用上正在学的东西"那部分（IO 读文件、集合分组）**

**这个项目对你的明确收益**：你会亲眼看到 **SQL 的 `GROUP BY`、Java 集合的分组、Stream 的 `groupingBy` 是同一件事的三种写法**。等你 W6 学 Stream 时，这三种会连成一条线——**这是很多人工作几年都没建立的联系。**
